Create Carousel container component with CSS scroll-snap for horizontal scrolling and IntersectionObserver for active card detection.

**User decision context:** Per 02-CONTEXT.md, use CSS scroll-snap for native snap-to-card behavior (no custom JS scroll physics). IntersectionObserver detects centered card.

**Component architecture:**
- Client Component (`'use client'` directive - uses browser APIs)
- Accept props: `entries: DailyEntry[]`, `isLoading?: boolean`
- State: `activeId: string | null` (currently centered card)
- Refs: `cardRefs: Map<string, HTMLElement>` for IntersectionObserver targets

**Implementation pattern (from 02-RESEARCH.md Pattern 2):**

```tsx
'use client'

import { useEffect, useRef, useState } from 'react'
import { DayCard } from './DayCard'
import { SkeletonCard } from './SkeletonCard'
import type { DailyEntry } from '@/lib/types'
import styles from './Carousel.module.css'

export function Carousel({ entries, isLoading = false }: Props) {
  const [activeId, setActiveId] = useState<string | null>(null)
  const observerRef = useRef<IntersectionObserver | null>(null)
  const cardRefs = useRef<Map<string, HTMLElement>>(new Map())

  useEffect(() => {
    // Create observer with center-detection configuration
    const observer = new IntersectionObserver(
      (entries) => {
        entries.forEach((entry) => {
          if (entry.isIntersecting) {
            const id = entry.target.getAttribute('data-id')
            if (id) setActiveId(id)
          }
        })
      },
      {
        root: null, // viewport as root
        rootMargin: '-50% 0px -50% 0px', // center 50% detection zone
        threshold: 0 // trigger immediately when entering zone
      }
    )

    observerRef.current = observer

    // Observe all cards
    cardRefs.current.forEach((card) => observer.observe(card))

    // CRITICAL: Cleanup on unmount (prevents memory leaks per RESEARCH.md Pitfall 1)
    return () => observer.disconnect()
  }, [entries])

  // Loading state: show skeleton cards
  if (isLoading) {
    return (
      <div className={styles.carousel}>
        {[...Array(3)].map((_, i) => <SkeletonCard key={i} />)}
      </div>
    )
  }

  return (
    <div className={styles.carousel}>
      {entries.map((entry) => (
        <DayCard
          key={entry.id}
          entry={entry}
          isActive={activeId === entry.id}
          ref={(el) => {
            // Ref callback pattern (from RESEARCH.md)
            if (el) {
              cardRefs.current.set(entry.id, el)
            } else {
              cardRefs.current.delete(entry.id)
            }
          }}
        />
      ))}
    </div>
  )
}
```

**CSS Module styling (Carousel.module.css):**

```css
.carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory; /* Force snap on x-axis */
  scroll-behavior: smooth; /* Smooth scrolling */
  gap: var(--space-lg);
  padding: var(--space-xl);
  
  /* Hide scrollbar but keep functionality */
  scrollbar-width: none; /* Firefox */
  -ms-overflow-style: none; /* IE/Edge */
}

.carousel::-webkit-scrollbar {
  display: none; /* Chrome/Safari */
}
```

**Why rootMargin '-50% 0px -50% 0px':** Per RESEARCH.md Pattern 2, negative percentages shrink the intersection zone. This creates a center-only detection area - only the card in the middle 50% of viewport triggers `isIntersecting: true`.

**Why scroll-snap-type mandatory:** Forces browser to always snap to a card (can't stop between cards). Alternative `proximity` allows stopping mid-scroll, which breaks the "one active card" pattern.

**Why threshold: 0:** Trigger as soon as element enters center zone (don't wait for 50% visibility). Immediate response feels more reactive.

**Why cleanup return:** Per RESEARCH.md Pitfall 1, IntersectionObserver persists after component unmounts unless explicitly disconnected. Without cleanup, observer callbacks fire on unmounted component → memory leaks and console errors.

**Why aria-hidden:** Skeleton cards are decorative placeholders, not meaningful content. Screen readers should skip them.

**Why vintage shimmer:** White shimmer (not blue/gray) over aged paper maintains leather journal aesthetic. Opacity 0.15-0.3 is subtle, not flashy.

**Why 2.5s animation:** Slower than typical 1.5s shimmer feels more "analog" and matches vintage journal vibe (not slick/digital).

**Why respect reduced motion:** Users with vestibular disorders can experience nausea from shimmer animations. `prefers-reduced-motion: reduce` disables animation for accessibility.
